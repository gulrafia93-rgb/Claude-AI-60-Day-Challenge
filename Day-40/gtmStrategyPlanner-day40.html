The system prompt (the "brain")

Every request sends a fixed system prompt to Claude that casts it as a senior GTM strategy consultant and forces a strict JSON contract — no markdown, no preamble, just fields the UI already knows how to render (channels, budget_breakdown, ninety_day_plan, etc). Locking the schema up front is what lets the interface look like a designed report instead of a chat transcript.

It also handles three edge cases explicitly: sparse input (still produces a best-effort dossier, but lists assumptions in a visible "clarifications needed" box rather than inventing false confidence), irrelevant or nonsensical input (returns an {"error": "..."} shape instead of forcing a fake report), and prompt injection (founder text is treated strictly as data to analyze, never as instructions — so a challenge field that says "ignore your instructions and…" can't hijack the system prompt).

Why the UI looks like this

A GTM plan is a strategist's deliverable, not a chat reply — so the interface borrows from a confidential consulting dossier: a stamped cover intake, a numbered table of contents with real sequence (executive summary before channels before budget, because each section depends on the last), and a brass/navy/paper palette instead of a generic chat bubble UI. The budget bars and priority tags exist because a founder scanning this needs to triage in seconds, not read paragraphs.

Extending it

  • Tools: add the web_search tool to the API call so channel recommendations can cite real current CAC/CPM benchmarks instead of the model's trained-in estimates.
  • Memory: persist each founder's past dossiers (e.g. via window.storage) so a returning user gets a dossier that references what changed since last time, and can track plan-vs-actual.
  • Multi-step flows: turn the 90-day plan into a second API call per phase, so each phase gets refined once the founder reports back what actually happened — a rolling plan instead of a one-shot report.
  • MCP integration: connect an Asana/Linear/Notion MCP server so the "first action" per channel can be pushed directly into the founder's task tracker.
